# 事件风暴工作坊 — 深度指南


## 事件风暴完整流程

```
业务目标/愿景
  → 场景与用户旅程
    → 事件风暴（命令/事件/实体/外部系统/异常）
      → 限界上下文（BC）与上下文地图
        → 聚合（不变式 + 事务边界）
          → 领域事件清单（语义/版本/幂等）
            → 领域模型 ⇄ 代码模型映射表
```

## 便签颜色规范

| 颜色 | 含义 | 格式 |
|------|------|------|
| 🟠 橙色 | 领域事件 | 动词过去式：OrderPlaced |
| 🔵 蓝色 | 命令 | 动词原形：Place Order |
| 🟡 黄色 | 聚合/实体 | 名词：Order |
| 🟢 绿色 | 读模型 | 名词：Order Detail Page |
| 🔴 粉色 | 外部系统 | 名词：Payment Gateway |
| 🟣 紫色 | 问题/争议 | 待讨论项 |

## 案例：保险投保业务流程

**命令清单**：
- 创建投保单、核保、生成缴费通知单、缴费、生成保单

**领域事件清单**：
- 投保单已创建、核保已通过、缴费通知单已生成、缴费已完成、保单已生成

**聚合识别**：
- 投保聚合（投保单聚合根、被保人、标的）
- 客户聚合（客户聚合根）
- 收款聚合（缴费通知单聚合根）
- 保单聚合（保单聚合根）

**限界上下文划分**：
- 投保上下文：投保聚合
- 客户上下文：客户聚合
- 收款上下文：收款聚合
- 保单上下文：保单聚合

## 聚合设计 5 步（实战案例）

以投保业务为例：

**第 1 步**：梳理所有实体和值对象（投保单、标的、客户、被保人）

**第 2 步**：选聚合根。判断：
- 是否有独立生命周期？
- 是否有全局唯一 ID？
- 是否可以创建或修改其它对象？

**第 3 步**：找出与聚合根紧密依赖的实体和值对象

**第 4 步**：画引用关系。聚合间通过 ID 关联

**第 5 步**：划分到限界上下文
