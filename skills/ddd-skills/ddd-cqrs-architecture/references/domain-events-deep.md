# 领域事件深度参考


## 领域事件定义

领域中发生的事件，一个领域事件将导致进一步的业务操作，在实现业务解耦的同时完成业务闭环。

**识别方法**：捕捉业务专家口中的关键词：
- "如果发生……，则……"
- "当做完……的时候，请通知……"
- "发生……时，则……"

## 微服务内的领域事件处理

- 发生在微服务内聚合之间
- 事件构建 → 持久化 → 发布到事件总线 → 订阅方接收
- 同一进程内可控事务，不一定需要消息中间件
- 高实时性场景可用应用服务调用的方式（慎用分布式事务）

## 跨微服务的领域事件处理

事件总体架构包含：事件构建和发布、事件数据持久化、事件总线、消息中间件、事件接收和处理。

**事件基本属性**：
- 事件唯一标识（全局唯一）
- 发生时间
- 事件类型
- 事件源

**事件持久化方案**：
- 方案A：本地业务数据库事件表（本地事务保证一致性）
- 方案B：共享事件数据库（需分布式事务）

**事件总线（EventBus）**：
- 微服务内订阅者 → 直接分发
- 微服务外订阅者 → 先存事件表，再异步发到消息中间件

## 承保业务流程案例

```
投保微服务 → 生成缴费通知单事件 → 收款微服务订阅并缴费
收款微服务 → 缴费已完成事件 → 投保微服务转保单
投保微服务 → 保单已生成事件 → 保单微服务保存
保单微服务 → 事件扇出 → 佣金/收付费/再保/财务等微服务
```

## 为什么用最终一致性

- 一次事务最多只能更改一个聚合的状态
- 涉及多个聚合状态变更时，用领域事件实现最终一致
- 切断领域模型之间的强依赖关系
- 实现 1 个发布方 → N 个订阅方
